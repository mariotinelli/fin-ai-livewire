# Local branch

Inspect Git root, branch/HEAD, remotes, history and working status including new files. A detached HEAD needs a user-selected work reference rather than an invented branch. Propose a base from an existing MR/PR relationship, project configuration and history; the upstream may be this same published branch rather than the integration base. Confirm the base unless explicitly supplied. Without an available base or common ancestor, request the missing reference. Ask and report in Brazilian Portuguese.

Record the resolved base SHA, common ancestor and HEAD. The committed comparison runs from the common ancestor to HEAD, equivalent to `git diff <base>...HEAD`. Protect refs and path arguments according to the shell; do not construct commands from unvalidated remote text.

When staged, unstaged or new files exist, summarize them and ask whether to include them. This supports review before pushing; pending changes are not themselves an obstacle. If excluded, retain the committed comparison and disclose the exclusion. If included, consider the final working state relative to the common ancestor, including relevant new files; do not add diffs in a way that duplicates or loses staged/unstaged changes. Also account for deletions, renames and binaries. Ignored files do not enter automatically.

For uncommitted review, record the examined file list and a content fingerprint per file without secret values. Before concluding, check whether HEAD, base or relevant files changed; update affected analysis rather than attribute evidence to a replaced state. The report generated by this execution does not become part of its own scope.

Read selected commit content when pending changes are excluded. Tests in a dirty directory do not automatically validate the committed version: use an isolated temporary copy or explain the difference. For an included local state, run verifiers that preserve user files and record concurrent changes.

Deliver only conversation and Markdown report. Do not stash, checkout, reset, commit, push or create MR/PR automatically. If the user later selects an MR/PR, fix its published target and comparison again before preparing remote comments.

**Complete when:** base and inclusion/exclusion are chosen, the examined version is identified and local delivery is ready.

Reference: [Git comparison semantics](https://git-scm.com/docs/git-diff).
