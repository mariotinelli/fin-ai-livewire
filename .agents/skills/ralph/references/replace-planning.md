# Substituir planejamento existente

Use quando solicitado ou quando tarefa/plano divergem materialmente. Leia plano, task.md, pai, Git e resultados já concluídos. Mostre a divergência e o impacto; preserve evidências e commits.

Edite o mesmo planning.md incorporando apenas o novo escopo aprovado e distinguindo resultados antigos de trabalho futuro. Preserve uma cópia histórica quando necessária para entender mudança autorizada; não duplique planos ativos. Não apague diretórios, estado legado ou commits para reiniciar o fluxo.

Apresente a versão alterada na conversa conforme [apresentação e decisão](../../plan-issue/references/planning-contract.md#apresentar-o-plano-e-receber-a-decisão), incluindo o impacto sobre o plano anterior. Autorização para versão anterior não abrange mudança material. Retome fases ainda necessárias pelos quatro gates Dev, Validação, Testes e Commit, conforme código atual; verificações antigas de host/diagnóstico são incorporadas sem alterar o aceite. Reutilize autorizações ainda válidas para o mesmo conteúdo, sem segunda confirmação após aprovação no pedido de execução.

**Concluído quando:** versão atual revisada e trabalho anterior preservado, sem reconstruir progresso fictício.
